# Terminal Selection

## Objective

The purpose of this document is to select the terminal emulator that will become the standard terminal for Project Kintsugi.

Rather than choosing a terminal based on popularity or personal preference, the decision follows the engineering principles established throughout the project.

The selected terminal should support the long-term goals of simplicity, productivity, maintainability, and a modern Wayland-based desktop.

---

## Background

The terminal emulator is one of the first essential applications in a minimal Hyprland environment.

It provides the primary interface for configuring the system, launching applications, inspecting the running environment, and performing administrative tasks during the migration from KDE Plasma.

Because the terminal will be used throughout the entire lifecycle of the project, its selection deserves explicit documentation.

---

## Evaluation Criteria

As defined in `terminal-emulator.md`, Project Kintsugi values:

- native Wayland support,
- active maintenance,
- stability,
- performance,
- clear documentation,
- simple configuration,
- long-term maintainability,
- compatibility with the project's engineering philosophy,
- straightforward integration with Fedora.

No single characteristic determines the decision.

Instead, the overall balance between these factors is evaluated.

---

## Candidate Terminals

### Kitty

Kitty is a mature GPU-accelerated terminal emulator with excellent Wayland support and broad adoption within the Linux desktop ecosystem.

It is actively maintained, well documented, and commonly used in Hyprland-based environments.

Its feature set is extensive, yet it remains suitable for both daily development work and long-term system maintenance.

---

### Ghostty

Ghostty is a modern GPU-accelerated terminal emulator focused on performance, portability, and native platform integration.

Its design philosophy aligns well with many of Project Kintsugi's engineering principles.

However, software quality alone is not sufficient to justify its adoption.

Distribution and long-term maintainability must also be considered.

---

### Other Alternatives

Other terminal emulators, including Foot, Alacritty, and WezTerm, were considered during the evaluation.

Each offers different strengths and trade-offs.

At the current stage of Project Kintsugi, none provides a sufficiently compelling advantage over Kitty to justify becoming the project's standard terminal.

---

## Fedora Evaluation

Project Kintsugi evaluated the availability of the primary candidates within the Fedora 44 environment.

The investigation confirmed that:

- Kitty is immediately available through the repositories currently used by the project.
- Kitty integrates naturally with the default Hyprland configuration, where the autogenerated configuration already expects Kitty as the default terminal.
- Ghostty is not available through the current Fedora package sources configured for the project.
- Selecting Ghostty would require introducing an additional distribution method without a clearly demonstrated engineering benefit.

These findings reinforce the project's preference for minimizing unnecessary complexity while maintaining a reproducible system.

---

## Decision

Project Kintsugi selects **Kitty** as its standard terminal emulator.

---

## Rationale

The decision is based on the overall engineering balance rather than a single technical feature.

Kitty offers:

- excellent Wayland support,
- active and mature development,
- comprehensive documentation,
- strong adoption within the Hyprland ecosystem,
- immediate compatibility with the current Fedora environment,
- seamless integration with the default Hyprland configuration.

Most importantly, Kitty satisfies the project's package source policy without requiring additional repositories or installation methods beyond those already introduced for Hyprland.

This reduces unnecessary complexity while supporting the project's long-term maintainability goals.

---

## Trade-offs

Kitty provides a larger feature set than Project Kintsugi currently requires.

Some advanced functionality may never be used during the project.

This additional complexity is considered an acceptable trade-off given the project's maturity, documentation quality, and ecosystem support.

---

## Future Review

Project Kintsugi recognizes that software ecosystems evolve.

This decision may be revisited if:

- Fedora begins providing a more suitable alternative,
- Kitty's maintenance significantly changes,
- another terminal offers a clearly superior engineering balance without increasing system complexity.

Until such conditions arise, Kitty will remain the project's standard terminal emulator.

---

## Conclusion

The terminal emulator is a foundational component of the desktop environment.

After evaluating both technical characteristics and integration with Fedora, Project Kintsugi selects Kitty as the terminal emulator that best supports the project's principles of simplicity, maintainability, reproducibility, and incremental system construction.
