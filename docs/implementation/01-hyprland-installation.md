# Hyprland Installation

## Objective

The objective of this implementation is to introduce the Hyprland compositor into the Fedora system without replacing the existing KDE Plasma desktop.

At this stage, Hyprland is installed only as an independent Wayland session.

The goal is not to configure a complete desktop, but to verify that the selected compositor can be installed successfully and start a functional graphical session.

This implementation marks the transition from architectural planning to incremental system integration.

---

## Background

During the first part of Phase 1, Project Kintsugi established the architectural foundations of the future desktop.

The project documented:

* the role of a desktop environment,
* the responsibilities of a Wayland compositor,
* the Wayland protocol,
* desktop portals,
* desktop components,
* the selection of Hyprland,
* the project's decision criteria,
* and the validation methodology.

With these concepts documented, the project is prepared to begin implementation while maintaining the engineering principles established during Phase 0.

Hyprland is introduced first because it is the central component around which the remaining desktop will be constructed.

---

## Scope

This implementation is intentionally limited.

Its responsibilities are to:

* install the Hyprland package,
* verify that the session becomes available,
* confirm that a Wayland session can be started,
* verify basic keyboard, mouse, and display functionality.

The implementation explicitly excludes desktop customization or the installation of additional desktop components.

Features such as status bars, launchers, notifications, wallpapers, authentication agents, and lock screens belong to later implementation stages.

---

## Validation Criteria

The implementation is considered successful when the following conditions are satisfied:

* Hyprland is installed successfully.
* A Hyprland session is available from the display manager.
* The graphical session starts correctly.
* Keyboard input functions normally.
* Mouse input functions normally.
* Connected displays are detected and usable.
* The session remains stable during basic interaction.

Passing these checks demonstrates that the architectural foundation of the future desktop has been successfully introduced.

---

## Observations

At this stage, the desktop is expected to be minimal.

The absence of desktop conveniences is intentional and should not be interpreted as an incomplete installation.

Project Kintsugi deliberately introduces one responsibility at a time in order to simplify validation, troubleshooting, and long-term maintenance.

A minimal but functional graphical session represents a successful outcome for this implementation.

---

## Next Step

Once Hyprland has been installed and validated, the project will proceed with the integration of additional desktop components following the established engineering workflow:

1. Understand the component.
2. Document the decision.
3. Implement incrementally.
4. Validate the implementation.
5. Record the result in version control.

Each subsequent implementation will extend the desktop while preserving a stable and well-understood system.

---

## Validation Results

The installation was validated on Fedora 44 KDE Plasma (Wayland).

---

### Installation

Hyprland was installed from the `lionheartp/Hyprland` COPR repository after verifying that no official Fedora package was available.

To avoid introducing desktop components before they were evaluated by the project, the installation was performed without weak dependencies:

```bash
sudo dnf install --setopt=install_weak_deps=False hyprland
```

Only the compositor and its required runtime dependencies were installed.

---

## Results

Validation confirmed the following:

* Hyprland was successfully installed.
* A new Wayland session (`hyprland.desktop`) was installed under `/usr/share/wayland-sessions`.
* SDDM detected the new session.
* The Hyprland session started successfully.
* Keyboard and mouse input were functional.
* Rendering and display output worked correctly.
* The autogenerated configuration was created under:
```
~/.config/hypr/hyprland.lua
```

The default configuration displayed a welcome screen and basic keybindings.

The default shortcut for launching Kitty (`SUPER + Q`) did not open a terminal because Kitty was intentionally not installed. This behavior was expected, as Project Kintsugi defers the selection of desktop components until each one has been individually evaluated.

---

## Conclusion

The installation objective for this implementation phase was achieved successfully.

Hyprland is now available as a functional Wayland session and provides the foundation for the incremental construction of the desktop environment.
