# Notification Daemon Installation

## Objective

The objective of this implementation is to introduce a notification daemon into the Hyprland session.

The notification daemon provides the desktop service responsible for presenting notifications generated by applications and other desktop components.

---

## Background

Previous implementations introduced the following foundational desktop components:

- Hyprland
- Kitty
- Fuzzel
- Dolphin
- Waybar

The next step is to provide a desktop notification service that enables applications to communicate information to the user through the standard desktop notification interface.

Following the project's evaluation process, Mako was selected because it provides native Wayland support, complies with the Freedesktop notification specification, and is available through the official Fedora repositories.

---

## Scope

This implementation is limited to:

- installing Mako;
- verifying its operation under the user session;
- validating its D-Bus activation mechanism;
- validating that desktop notifications are displayed correctly.

Notification appearance, styling, advanced configuration, and notification history are outside the scope of this implementation.

---

## Installation

Mako will be installed from the official Fedora repositories.

Following the project's package policy, weak dependencies will be intentionally disabled during installation.

```bash
sudo dnf install --setopt=install_weak_deps=False mako
```

---

## Session Integration

Mako provides a D-Bus service and integrates naturally with the user session.

During validation, the notification daemon started successfully without requiring explicit startup commands in the Hyprland configuration.

Project Kintsugi therefore relies on the upstream activation mechanism rather than launching Mako through Hyprland.

This approach preserves the intended integration model while avoiding unnecessary compositor-specific configuration.

---

## Validation

The implementation is considered successful when:

- Mako installs successfully.
- The notification daemon can be activated within the user session.
- Desktop notifications are displayed correctly.
- Notifications remain responsive throughout the session.
- No explicit Hyprland startup configuration is required.

---

## Results

Validation confirmed the following:

- Mako was successfully installed from the official Fedora repositories.
- The notification daemon was activated successfully within the user session.
- Desktop notifications were displayed correctly using the standard notification interface.
- No additional Hyprland startup configuration was required.
- The implementation follows the upstream D-Bus activation model.

Desktop notifications were validated using the `notify-send` utility.

A test notification was successfully displayed, confirming correct integration with the desktop notification service.

---

## Conclusion

The implementation objective was achieved successfully.

Project Kintsugi now includes a native Wayland notification service that integrates with the user session through the upstream D-Bus activation mechanism while preserving the project's modular architecture and standards-compliant desktop design.
